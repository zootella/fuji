# From the Mac to Linux: the video window, and the buttons fuji draws on it

Written on the Mac mini, 2026-10-21, and brought up to date on the Windows box on 2026-10-22, when `v` became a process of its own everywhere but the Mac. Read this, then talk to the user before changing anything; a letter starts a conversation rather than settling one.

## What changed

v in the main window, whatever it shows, or in a video window opens a video window, `VideoWindow.vue`, a native window of its own beside the main one, whose title bar comes off and in whose place fuji draws its own minimize, maximize and close, the same on every platform rather than a copy of any one Linux desktop's. `window-check.md` at the root says how it behaves as the user meets it, and the essay atop `VideoWindow.vue` is the rule. None of it has been built for Linux yet.

## What only Linux can check

- **A copy of fuji for every v.** Everywhere but the Mac one window is one process, so `window_new` starts a copy of fuji with `--note=Video` on its command line, from `current_exe`, and the copy's first window is the video window, as for a double-click in the file manager; it waits on the copy from a thread so a closed window's process is collected rather than left a zombie while the main window runs. It ran on the Windows box on 2026-10-22 and has never run here, the flatpak's sandbox included. Press v in the main window: a video window should appear on top in a process of its own, and v twice should give two. Close the main window with a video window still open: the video window should stay, and closing it should leave no fuji process behind.
- **The drag, on Wayland.** The page asks tao to drag only once the pointer has moved 4 CSS pixels with the button down, so the request comes on a motion rather than on the press. tao answers with GTK's `begin_move_drag(1, x, y, 0)`, current time and no press event (tao 0.35.3's Linux event loop), and on Wayland a compositor starts a move only for a press it can match. If a drag from the middle of the video window moves it under X11 and not under Wayland, that is the place to look.
- **The resize band and the close button.** On a window with no title bar, tao shows a resize arrow within 5 pixels of each edge and starts the window manager's resize on a press there. Fuji's close button sits flush in the top right corner, so its outermost pixels lie inside that band, and a press on the button's top right corner may start a resize instead of closing the window. How many pixels it is, and whether anyone would hit it, is the answer wanted.
- **Minimize and maximize.** On Wayland a minimized window cannot bring itself back, so a minimized video window should come back from the dock, Activities or Alt+Tab. Maximize should fill the work area below the top bar, with the middle button showing restore, and a second press bring the window back where it was.
