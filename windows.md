# To the Windows box: the preview, and where a window really is

Written on the Mac mini, 2026-09-27, alongside PreviewTable. Read this, then talk to the user before changing anything; a letter starts a conversation rather than settling one.

## What changed

**A double-click on a picture now opens a preview.** The shell takes the window's title bar off and fits the window around the picture, as tall or as wide as the work area allows but never past twice its size, and places it in the larger side of the work area away from the pointer; `rectPreview` in `library.js` has the rule. A click on the picture swaps in the diamond table, fullscreen, with the card where the preview stood. From there the table is only ever fullscreen and the contact sheet only ever a window: a double-click on the table goes to the sheet, a double-clicked thumbnail goes back to the table, and Escape on any table closes the window, as does the preview losing focus. `PreviewTable.vue` has the preview's behavior, and the essay in `Shell.vue` that begins "The sheet lives in a window" has the window's part.

**The page can now read and place its window exactly**, through `window_frame` and `window_frame_set` in `window.rs`, in CSS pixels, meaning the frame a person sees. On the Mac, Tauri's outer rectangle already is that. On Windows 10 and 11 it is not, because it includes the invisible resize borders, about 7 pixels on the left, right and bottom at 100 percent. The essay above `Frame` in `window.rs` has the whole of it. `window_seen` is the one function that answers, and today it passes Tauri's outer rectangle through on every platform.

**And the page now places every window itself**, before the reveal, and fuji remembers only the size the user last gave the contact sheet's window. A sheet opens at that size when it fits the work area, and at 0.6 of the work area's width and 0.85 of its height when it does not, though never wider than 16:9, somewhere random inside it either way, from the presets in `library.js`, and those portions are meant to describe the frame a person sees. So on Windows the sheet's window is 7 pixels smaller on each side than intended until `window_seen` is corrected. Rust no longer cascades or corrects a window's position at all.

**Registering what fuji can open moved into the page, and now only an installed copy does it.** `associate.rs` is gone. Its policy is `associate.js`, over three general commands in `registry.rs`, `registry_get`, `registry_set` and `registry_notify`; the keys, the values and their order are unchanged. The new part is the gate: `associateRegister` goes ahead only when the running executable's folder, from `paths_executable` in `paths.rs`, equals the `InstallLocation` the installer recorded under `HKEY_CURRENT_USER\Software\Microsoft\Windows\CurrentVersion\Uninstall\Fuji`, quotes removed. That value and that key were read out of Tauri's NSIS template on the Mac, not seen on this machine. Before, any release build registered, including one run out of `target/release`; now none of those does, so a registry still pointing at a `target/` executable from earlier testing is repointed by the installed copy's first launch.

## What only this machine can do

1. **Write the Windows body of `window_seen`.** `DwmGetWindowAttribute` with `DWMWA_EXTENDED_FRAME_BOUNDS` gives the visible frame in physical pixels. The risk is that fuji places every window while it is still hidden, and that attribute is known to answer badly for a window that has not been shown. So measure it both ways: the same window hidden and shown, at 100 percent and at another scale. If the hidden answer is wrong, calculate the invisible border from the window's style and DPI with `AdjustWindowRectExForDpi` and the frame metrics instead. `window_seen_move` and `window_frame_set` already subtract whatever difference `window_seen` reports, so nothing else should need to change. Checking it from the Mac is not possible, because `cargo check --target x86_64-pc-windows-msvc` fails inside Tauri's build script, as `CLAUDE.md` notes.
2. **See whether the preview has invisible borders at all.** A window without decorations may have none, because tao makes the whole window its client area. Compare `window_frame` against Tauri's outer rectangle on a preview and on an ordinary window.
3. **Launch from Explorer, and check the preview has focus.** The preview closes on losing focus, but only after it has had it once. If Explorer does not hand focus to the new process, the preview never closes by itself, which is safe but wrong.
4. **Double-click the table after a preview, and watch the sheet appear.** `sheetFromPreview` in the shell hides the window, leaves fullscreen, places the window and turns its title bar on, then shows it, so the user never sees it leave the preview's place. On Windows, tao leaves fullscreen with `SetWindowPlacement` and the placement it saved on the way in, which carries a show command, so the window may come back into view before it has been placed. If it does, the user sees it flash at the preview's frame. The first thing to try is hiding it again straight after leaving fullscreen, which costs nothing on the Mac; if a flash survives that, talk to the user before going further.
5. **Select several pictures and press Enter.** Explorer starts one fuji per file. Each new preview takes focus from the one before, so all but the last should close. Worth watching once, to see it happen cleanly rather than leave windows behind.
6. **Build with `pnpm installer`, install what it makes, launch once, and check that fuji still registers.** With `log.record` on in `fuji.toml`, the log, which is only written when fuji closes normally rather than being killed (`performance.md` has the `taskkill` without `/F` that does that), should carry a line reading `associate: 10 types registered, N values written`; no line means the gate said no, and the two folders it compared are the one holding the running `fuji.exe` and the `InstallLocation` value above, which `regedit` shows, compared without regard to case. Then right-click a `.webp`, Open with, and look for Fuji, and confirm the ProgIDs under `HKEY_CURRENT_USER\Software\Classes\Fuji.*` name the installed `fuji.exe` rather than one in `target/`. Also launch `target/release/fuji.exe` directly once and confirm it writes nothing. And then uninstall, and install again into a folder of your own, from the folder page or with `/D=C:\Some\Folder` on the installer's command line, and confirm that copy registers too, which is the case the gate was written for. Uninstall first because a second install over the first lands on the installer's reinstall page, and its folder page arrives filled in with the old location.

Put what you measure in `window.rs` and in the shell's window essay, with the machine and the date, and what item 6 finds in `associations.md`. Then retire this letter, as its predecessors were.
